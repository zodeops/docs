Zode gives your coding agents Linux VMs to work in. Each sandbox is a microVM (Cloud Hypervisor on KVM) with its own kernel, disk and memory. You drive it from the `zode` CLI, the TypeScript SDK, the HTTP API at `https://api.zode.dev`, or an MCP server your agent talks to.

## What you can do

- **Run commands.** Run a command and get its output and exit code, or open an interactive shell.
- **Fork.** Copy a running or stopped sandbox, memory and disk included, into a new running sandbox.
- **Snapshot and restore.** Save a sandbox's disk and memory, then roll the same sandbox back to it later.
- **Stop and start.** Stopping hibernates the sandbox: disk and memory are kept and compute billing stops. Starting picks up where it left off.
- **Drive a browser.** Switch on Chrome in the sandbox and connect Playwright, Puppeteer or browser-use over CDP.
- **Use a Linux desktop.** Take screenshots, click and type, or embed a live view. The desktop is on the Pro plan and up.
- **Build custom images.** Build an image from a Dockerfile or a list of setup commands, and start sandboxes from it with your tools already installed.
- **Keep secrets out of the VM.** A sandbox sees a placeholder value. The host swaps in the real secret only on HTTPS requests to the hosts you allow.

## Sizes

Every sandbox has one of four fixed sizes. Compute is billed per second while the sandbox runs.

| Size | vCPU | RAM | Disk | Price/hour |
|---|---|---|---|---|
| `small` | 2 | 4 GB | 50 GB | $0.0175 |
| `default` | 4 | 8 GB | 50 GB | $0.035 |
| `large` | 8 | 16 GB | 110 GB | $0.070 |
| `xlarge` | 16 | 32 GB | 250 GB | $0.140 |

A sandbox made without a size is `small`, from the CLI, the SDK, the API or MCP. The size named `default` is not the default. Storage is billed separately and is free for each sandbox's first 48 hours; see [Pricing](/pricing).

Sandboxes run in `eu-central`, on Google Cloud in europe-west1 (Belgium). It is the only region.
